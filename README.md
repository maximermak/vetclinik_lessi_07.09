# «Лессі» — сайт ветеринарної клініки

Лендінг ветклініки у Харкові (вул. Нескорених, 4а/1) з формою онлайн-запису.
Заявки миттєво надходять адміністратору в Telegram.

**Стек:** Node.js + Express + EJS, без збірки та фронтенд-фреймворків.

## Запуск

```bash
npm install
cp .env.example .env   # якщо .env ще немає
npm start              # http://localhost:3000
```

Для розробки з автоперезапуском: `npm run dev`.

## Налаштування Telegram

1. Токен бота вже прописаний у `.env` (`TELEGRAM_BOT_TOKEN`) — бот
   [@lessivet_bot](https://t.me/lessivet_bot).
2. Визначте, **куди** бот надсилатиме заявки:
   - **особисті повідомлення** — відкрийте [@lessivet_bot](https://t.me/lessivet_bot)
     і натисніть «Start»;
   - **спільна група** (рекомендовано — бачить уся адміністрація) — створіть групу,
     додайте туди бота і напишіть у ній будь-яке повідомлення.
3. Виконайте:

   ```bash
   npm run chat-id
   ```

   Скрипт покаже список чатів з їхніми ID.
4. Скопіюйте потрібний ID у `.env`:

   ```
   TELEGRAM_CHAT_ID=-1001234567890
   ```

5. Перезапустіть сервер. Перевірити готовність: `curl localhost:3000/health`
   → поле `"telegram": true`.

Зараз у `.env` вже прописаний особистий чат власника. Коли зʼявиться спільна
група адміністрації — замініть `TELEGRAM_CHAT_ID` на її ID (у груп він
відʼємний, напр. `-1001234567890`).

## Деплой на Vercel

Проєкт підготовлений: `api/index.js` експортує застосунок як
serverless-функцію, `vercel.json` спрямовує туди всі запити й додає
теку `views/` у бандл (EJS-шаблони читаються під час виконання, тож
трасувальник залежностей сам їх не підхопить).

### Порядок дій

1. Залийте репозиторій на GitHub і імпортуйте його на
   [vercel.com/new](https://vercel.com/new). Фреймворк — **Other**,
   команду збірки лишіть порожньою: збирати тут нічого.
   Альтернатива без GitHub — `npx vercel` у теці проєкту.
2. Додайте змінні оточення (**Settings → Environment Variables**).
   Файл `.env` у git не потрапляє і на Vercel не їде — значення
   треба перенести руками з локального `.env`:

   | Змінна | Значення | Обовʼязково |
   |---|---|---|
   | `TELEGRAM_BOT_TOKEN` | токен бота [@lessivet_bot](https://t.me/lessivet_bot) з `.env` | так, інакше заявки нікуди не підуть |
   | `TELEGRAM_CHAT_ID` | ID чату з `.env` | так |
   | `SITE_URL` | `https://ваш-домен` (без слеша в кінці) | бажано |
   | `GOOGLE_MAPS_API_KEY` | ключ Places API (New) | ні, але без нього рейтинг не показується |

3. Задеплойте й перевірте: `curl https://ваш-домен/health` має
   віддати `"telegram": true`. Потім надішліть тестову заявку з
   сайту — вона має прийти в Telegram.
4. Підключіть свій домен (**Settings → Domains**) і одразу після
   цього впишіть його в `SITE_URL`, інакше `og:image` і canonical
   вестимуть на адресу конкретного деплою, а не на постійну.

`SITE_URL` можна не задавати — тоді підставиться домен самого деплою
(`VERCEL_URL`). Але для прев'ю посилань у Telegram і соцмережах
краще вказати постійний домен: адреса деплою змінюється щоразу.

### Що ще задано в `vercel.json`

- **`regions: ["fra1"]`** — функція виконується у Франкфурті.
  За замовчуванням Vercel ставить США, а це зайві ~150 мс на кожен
  запит для відвідувача з Харкова.
- **Заголовки безпеки** для всіх відповідей: `nosniff`,
  `Referrer-Policy`, `X-Frame-Options`.
- **Річний кеш для `/css`, `/js`, `/img`.** Це безпечно лише тому,
  що всі посилання на статику в розмітці мають мітку версії
  (`?v=<хеш коміту>`) — після релізу адреса змінюється й браузер
  тягне свіжий файл. Якщо колись прибрати мітку з шаблонів,
  цей заголовок теж треба прибрати, інакше правки CSS не доїдуть
  до тих, хто вже був на сайті.

Що працює інакше в serverless:

- **Мітка версії статики** — локально це час зміни файлу, на Vercel
  файли з `public/` віддає CDN і в бандлі функції їх немає. Тому там
  міткою стає хеш коміту: новий на кожен реліз, кеш скидається так само.
- **Рейтинг Google** оновлюється ліниво — при першому запиті після
  протухання кешу, бо таймер між викликами функції не виживає.
- **Ліміт заявок** (5 за 10 хвилин) рахується в памʼяті процесу, а
  instances різні — на Vercel захист послаблюється. Від ботів лишається
  поле-приманка. Якщо спам стане проблемою, потрібне зовнішнє сховище
  (Upstash Redis) або капча.
- **Статика віддається CDN, а не застосунком.** Файли з `public/`
  Vercel знаходить раніше, ніж застосовує rewrite на функцію, тому
  `express.static` у serverless фактично не задіяний. Через це ж
  `views/**` доводиться додавати в бандл явно.

Форма надсилає заявку на `/lead`; `/api/lead` лишається як синонім,
бо теку `api/` на Vercel зарезервовано під функції.

## Деплой на власний сервер (Hetzner)

У теці `deploy/` лежить усе потрібне. Скрипти ідемпотентні — повторний
запуск нічого не ламає.

**Перший раз**, на чистому Debian/Ubuntu від root:

```bash
git clone https://github.com/maximermak/vetclinik_lessi_07.09.git /tmp/lessi
bash /tmp/lessi/deploy/setup.sh              # поки без домену — HTTP на IP
```

Скрипт ставить Node.js, Caddy, заводить системного користувача `lessi`,
кладе код у `/opt/lessi`, вмикає systemd-юніт і фаєрвол (22/80/443).

Секрети скрипт не приймає — щоб вони не світилися в списку процесів.
Після нього покладіть `.env` окремо:

```bash
scp .env root@СЕРВЕР:/opt/lessi/.env
ssh root@СЕРВЕР 'chown lessi:lessi /opt/lessi/.env && chmod 600 /opt/lessi/.env && systemctl restart lessi'
```

**Коли DNS уже вказує на сервер** — перезапустіть із доменом, і Caddy
сам візьме сертифікат Let's Encrypt:

```bash
bash /opt/lessi/deploy/setup.sh lessivet.com
```

Важливо: на час отримання сертифіката запис у Cloudflare має бути
**DNS only** (сіра хмарка). За увімкненим проксі перевірка HTTP-01 не
дійде до сервера. Отримали сертифікат — вмикайте помаранчеву хмарку
й ставте SSL/TLS у режим **Full (strict)**.

**Оновлення** після пушу в `main`:

```bash
ssh root@СЕРВЕР 'bash /opt/lessi/deploy/update.sh'
```

Корисне: `journalctl -u lessi -f` — лог застосунку (туди ж падають
заявки, якщо Telegram недоступний), `systemctl status caddy` — стан
проксі.

### Переїзд на сервер клієнта

Застосунок не зберігає стану, тож переносити нічого: на новому сервері
проганяєте `setup.sh`, кладете `.env`, міняєте A-запис у Cloudflare.
Старий сервер після цього можна просто видалити.

## Деплой на постійний процес

Railway, Render, Fly.io чи VPS — там нічого адаптувати не треба:
`npm start`, змінні оточення ті самі. Таймер рейтингу й ліміт заявок
працюють повноцінно.

## Структура

```
server.js              маршрути та віддача сторінки
src/data.js            увесь контент: послуги, графік, телефони, відгуки, FAQ
src/telegram.js        формування та надсилання повідомлення в Telegram
src/validate.js        перевірка полів заявки
views/index.ejs        головна сторінка
views/partials/        шапка, підвал, набір SVG-іконок
public/css/style.css   стилі (палітра — у CSS-змінних на початку файлу)

public/img/pets/       мальовані портрети пацієнтів (кіт, собака, свинка…)

```

## Правки контенту

Майже все редагується в одному файлі — `src/data.js`:
телефони, графік роботи, перелік послуг, кого лікуємо, переваги, відгуки, FAQ.

Адреса, телефон, посилання на Google Maps і відгуки — реальні, з картки
клініки (вул. Нескорених, 4а/1 — колишня Героїв Праці). Російськомовні
відгуки перекладені українською, зміст не змінювався.

### Що на сайті свідомо НЕ стверджується

Сайт не приписує клініці нічого, що не підтверджено даними з її картки
Google або відгуками власників:

- **немає вигаданого рейтингу.** Оцінка показується лише тоді, коли
  реально прийшла з Google Places API (див. нижче). Без ключа замість
  цифри стоїть посилання «Відгуки власників у Google Maps»;
- **немає фотографій клініки.** У проєкті лише мальовані ілюстрації
  (`public/img/pets/`). Коли клініка дасть власні знімки приміщення
  та лікарів — їх можна поставити замість або поруч з ілюстраціями.
  Ставити чужі фото не можна: це неправдиве твердження про приміщення;
- **немає стажу «N років практики»** та переліку обладнання —
  ці цифри нема звідки перевірити.

Кілька відгуків у Google критикують санітарні умови, ціни та години
роботи. Тому в текстах зроблено акцент на тому, що можна виконати:
графік без вихідних вказано явно, у FAQ окремо сказано про останній
прийом о 18:30, а вартість обіцяно озвучувати до початку прийому.

## Рейтинг з Google

Оцінку та кількість відгуків показуємо **лише живі**. У `src/data.js`
поля `rating` і `reviewsCount` навмисно `null`: без ключа Google блок
у героєві перетворюється на просте посилання на сторінку клініки в
Google Maps, а `aggregateRating` не потрапляє в розмітку schema.org.

Щоб зʼявилися цифри, додайте в `.env` ключ `GOOGLE_MAPS_API_KEY` —
сервер оновлюватиме їх двічі на добу через Places API (New):

1. У Google Cloud Console увімкніть **Places API (New)** і створіть ключ.
2. Впишіть його в `.env` і перезапустіть сервер.
3. Перевірка: `curl localhost:3000/health` → у полі `googleRating`
   має зʼявитись `"live": true`.

Оновлення відбувається у фоні за таймером, тому запити відвідувачів ніколи
не чекають на відповідь Google. Якщо Google недоступний або ключ невірний —
блок з оцінкою просто не показується, нічого не ламається.

Place ID клініки лежить у `src/data.js` (`clinic.placeId`) —
`ChIJa5jbqYanJ0ER52pJPC8fK_o`, вирахуваний з пари ідентифікаторів
`0x4127a786a9db986b:0xfa2b1f2f3c496ae7` у посиланні на картку Google Maps.
Перевірити його можна тим самим `curl localhost:3000/health`: якщо
`"live": true` — Google віддав дані саме для цієї клініки.

Палітра сайту побудована навколо імені клініки (Лессі — колі) і задана
змінними на початку `public/css/style.css`: `--green`, `--amber`,
`--dark`, `--cream`.

## Форма запису

Форма існує у двох місцях і рендериться з одного файлу
`views/partials/form.ejs` (параметр `prefix` робить id унікальними):

- секція «Онлайн-запис» на сторінці;
- модальне вікно, яке відкривають усі кнопки «Записатись»
  (`data-modal-open`). Кнопка в картці послуги ще й підставляє цю послугу
  в поле — через `data-service`.

Поля: вид тварини (кіт / собака / інша), ім’я, телефон з маскою,
вік тварини, послуга, дата й час візиту та коментар. Вік у повідомленні
відмінюється українською: `1 рік`, `3 роки`, `5 років`, `8 місяців`.

Власні контроли замість системних — сегментований перемикач, лічильник
віку, випадний список і календар — описані в кінці `public/css/style.css`
і оживають у `public/js/app.js`. Список підтримує клавіатуру:
стрілки, Home/End, Enter, Escape.

Календар сам рахує вільні слоти з графіка клініки (`scheduleByWeekday`
у `src/data.js`): крок 30 хвилин, останній слот — за 30 хвилин до закриття,
на сьогодні показуються лише часи не раніше ніж через годину. Дні, коли
запис уже неможливий, стають неактивними. Записатись можна на 60 днів уперед.

## SEO та GEO

Крім звичайної мета-розмітки й Open Graph, застосунок віддає три
службові адреси. Вони згенеровані з `src/data.js`, тож не розходяться
з тим, що написано на сторінці:

| Адреса | Навіщо |
|---|---|
| `/robots.txt` | дозволяє індексацію, вказує на карту сайту |
| `/sitemap.xml` | одна сторінка — головна; `/privacy` навмисно поза картою, бо має `noindex` |
| `/llms.txt` | стисла вижимка фактів для генеративних пошукових систем |

Віддаються маршрутами, а не файлами з `public/`, бо всередині потрібен
абсолютний домен — а він відомий лише під час виконання (`SITE_URL`).

Дату в `sitemap.xml` беремо з `clinic.contentUpdated` — оновлюйте її
руками, коли міняєте зміст сторінки.

**Структуровані дані** — два блоки JSON-LD:

- `VeterinaryCare` — назва, адреса, координати, графік, телефон,
  перелік послуг, посилання на картку Google. `aggregateRating`
  додається **лише** коли рейтинг реально прийшов з Places API;
- `FAQPage` — усі питання з блоку FAQ. Саме він дає шанс потрапити
  в розширений сніпет Google і в відповіді AI-пошуковиків.

**Локальні орієнтири.** Люди шукають «ветклініка Салтівка», а не
«ветклініка вул. Нескорених», тому район і найближче метро винесені
в `clinic.district` / `clinic.metro` і згадані в тексті, описі
сторінки та `llms.txt`. Відстань до метро порахована з координат
(~300 м) — **перевірте на місці**, перш ніж лишати це твердження.

## Політика конфіденційності

Сторінка `/privacy` (`views/privacy.ejs`) складена за Законом України
«Про захист персональних даних» № 2297-VI: хто володілець даних, що
збираємо, навіщо, кому передаємо (Telegram як канал доставки), скільки
зберігаємо, права людини за статтею 8.

У формі є обовʼязковий чекбокс згоди — його перевіряє і браузер,
і сервер (`required` у розмітці можна обійти, тому дублюємо
в `src/validate.js`).

**Обовʼязково заповнити перед запуском** — `clinic.legal` у `src/data.js`:
назва ФОП/ТОВ, РНОКПП або ЄДРПОУ та пошта для звернень. Зараз там
заглушки в кутових дужках, і без них сторінка юридично неповна.
Текст написаний як робоча основа — перед публікацією варто показати юристу.

## Захист форми від спаму

- приховане поле-приманка (honeypot) — заповнені ботом заявки тихо відкидаються;
- обмеження: не більше 5 заявок з однієї IP-адреси за 10 хвилин;
- валідація імені та номера телефону на сервері.

Якщо заявку не вдалося доставити в Telegram, вона друкується в лог сервера —
не загубиться навіть при збої месенджера.

## Деплой

Потрібен Node.js 18+. На сервері задайте змінні `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHAT_ID`, `PORT` та запустіть `npm start` під наглядом
процес-менеджера (pm2, systemd). Файл `.env` у git не потрапляє.
